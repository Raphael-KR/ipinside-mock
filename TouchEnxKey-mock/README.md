# TouchEnxKey-mock

기존 IPinside Mock 메뉴바 앱에 추가할 기능입니다. 전용 코드와 문서는 이 폴더에서
관리하고, 공통 기능은 상위 프로젝트와 함께 사용합니다.

## 이번 작업의 목표와 범위

목표: `https://pay.tmoney.co.kr`의 TouchEn nxKey 설치 확인에 대응한다.
범위: 공개 검사 코드 조사, 설치 확인 호환 기능 구현, 기존 메뉴바 앱 연결.
완료 조건: 확인된 설치 검사 계약에 대응하고 기존 IPinside 기능과 함께 제어할 수 있다.
제외 범위: 키보드 보안·암호화 구현, 로그인 실행, 계정·결제 데이터 변경.
검증: 공개 소스 근거 대조, 로컬 계약 검사, 앱 컴파일. 사이트 동작 확인 여부는 별도 기록한다.

2026-10-30 사용자 결정: 티머니 페이 사이트에서 로그인을 막는 TouchEn nxKey의
설치 확인만 대응한다. 키보드 입력·로그인 처리 호환은 구현 범위에 포함하지 않는다.

## 확정된 구성

```text
ipinside-mock/
├── src/
│   ├── main.swift           # 기존 메뉴바 앱과 IPinside 구현
│   └── Shared/
│       └── PythonServerProcess.swift  # 공통 자식 프로세스 관리
├── TouchEnxKey-mock/
│   ├── README.md
│   ├── IMPLEMENTATION.md    # 공개 근거, 구현 계약, 검증 기록
│   ├── TouchEnNxKeyServer.swift
│   └── touchen_nxkey_server.py
├── build.sh                # 공통 앱 빌드
└── generate_icon.swift     # 공통 아이콘 생성
```

- 별도 메뉴바 앱이나 별도 Git 저장소를 만들지 않는다.
- 기존 메뉴바 앱과 빌드·번들·아이콘을 재사용한다.
- TouchEnxKey 전용 소스, 프로토콜 조사 문서, 기능별 검증 자료는 이 폴더에 둔다.
- 공통 코드가 실제로 필요해지면 기존 `src/`에서 분리하여 두 기능이 함께 사용한다.
  아직 사용처가 없는 공통 프레임워크를 먼저 만들지 않는다.
- 기존 IPinside의 요청값, 포트, 인증서와 `captured.json`을 TouchEnxKey용으로
  덮어쓰지 않는다. TouchEnxKey에 필요한 통신·데이터 구조는 확인 후 정한다.

## 사용 방식

1. 메뉴의 **TouchEn nxKey · 티머니 → 설치 확인 시작**을 선택한다.
2. 기존 IPinside에서 사용하던 공통 TLS 인증서와 개인 키를 재사용한다. 인증서가
   준비되지 않았다면 **공통 인증서 설정…**에서 복사·신뢰 등록을 선택한다.
3. 티머니 사이트는 `wss://127.0.0.1:34581`의 설치 확인 응답을 사용한다.
4. **설치 확인 중지** 또는 앱 종료 시 전용 자식 프로세스를 중지한다.

IPinside 응답 캡처는 TouchEn 기능의 실행 조건이 아니다. 두 기능은 별도 포트를
사용한다. 원본 TouchEn 확장 프로그램이 우선되는 브라우저 구성은 별도 확인이 필요하다.

서버는 설치 버전 확인과 최소 초기화·준비 응답만 제공한다. 키보드 보호·E2E 암호화를
구현하지 않으며 로그인·결제를 수행하지 않는다. 요청 인자에 포함될 수 있는 입력값을
사용하거나 로그·파일에 저장하지 않는다.

## 현재 검증 범위

개발 단계에서 에이전트는 사용자 결정에 따라 **정적 검사와 빌드만** 수행했다.
합성 요청 생성, 인증서·개인 키 읽기, 임시 서버 실행과 실제 페이지 재검사는 하지 않았다.

이후 사용자가 티머니에서 정상 동작을 확인했다고 보고했다. 이 사용자 확인은
에이전트가 직접 수행한 통합 시험과 구분한다. 정확한 브라우저 버전, 설치 경로,
로그인 완료 여부, 종료 시 프로세스 정리는 별도로 확인하지 않았다.

v1.1.0 릴리스는 이 구현을 포함하며, 자세한 기록은 [구현 계획](IMPLEMENTATION.md)과
[릴리스 기록](../docs/releases/v1.1.0.md)을 따른다.
